# 03. 화면과 UI

## 1. 공통 원칙

- 구현은 HTML, CSS, JS와 ES 모듈이다. 상태는 하나의 저장소 객체에 두고, 서버 이벤트가 오면 저장소를 바꾸고 화면을 다시 그린다. [제안]
- 화면은 `GameTransport` 인터페이스만 보고 서버와 대화한다(07 문서). 웹소켓 구현과 목 구현을 같은 코드로 갈아끼운다. [확정]
- UI는 판정을 계산하지 않는다. 금지어 검사(`checkPrompt`)는 전송 전 미리 보기용이고, PASS/RETRY, 점수, 시간, 페널티는 서버 이벤트로만 바꾼다. [확정]
- 한글 입력(IME) 조합 중에는 글자 수를 센 값이 흔들리므로 조합이 끝난 뒤 검사한다. [제안]
- 글자 수 카운터는 `countChars`를 쓴다. 공백과 줄바꿈도 센다. [확정]
- 캐릭터는 고양이, 비둘기, 강아지, 씹덕 4종이다. 기존 게임의 캐릭터와 이미지, 로고, 이름, 에셋은 쓰지 않는다. [확정]
- 캐릭터 그림은 자체 제작(CSS, SVG, 이모지 조합)이다. 누가 그릴지는 모른다. [미정]

## 3. 대전 화면(S10) 배치 [제안]

```
┌──────────────────────────────────────────────────────────┐
│ [내 프로필: 캐릭터·닉네임]   [ 내점수  3 : 2  상대점수 ]   [상대 프로필] │
│ [연속 PASS ●●○]            [ ▓▓▓▓▓▓░░░░ 시간 바 / 10초 카운트 ]  [상대 연속 ●○○] │
├───────────────────────────┬──────────────────────────────┤
│ [내 캐릭터]  [말풍선·이모지]   │ [상대 캐릭터]  [말풍선·이모지]    │
│  ┌ 주제문 룰렛(공통, 중앙) ┐   │  (상태: 입력 중/AI 답변/정지)     │
│  주제문 · 분량 · 필수어 3개   │                              │
│ ┌ 내 설명창 ───────────┐   │ ┌ 상대 설명창(읽기 전용) ───┐    │
│ │ AI 답변 재생/평가 연출 │   │ │ 상대의 AI 답변 재생        │    │
│ └──────────────────┘   │ └──────────────────┘    │
│ [프롬프트 입력창 ........ 글자수/제한] [전송]  [이모지 줄]  [나가기] │
└───────────────────────────┴──────────────────────────────┘
```

- 두 플레이어 영역을 좌우로 나란히 놓고 상대 상태를 계속 보여 주는 구조는 레퍼런스에서 참고했다. [확정]
- 주제문 룰렛은 두 사람에게 같은 내용이라 화면 위쪽 가운데에 한 번만 둔다. 문제가 바뀔 때 슬롯이 돌아가는 연출을 한다. [제안]
- 상대 영역에는 프롬프트를 보여 주지 않는다. AI 답변과 상태(입력 중, AI 답변 중, 평가 중, 입력 정지)만 보여 준다. [확정]

## 4. 대전 화면 요소별 상태와 연출

### 4.1 프롬프트 입력창
- 입력하면 글자 수 `현재/제한`을 보여 주고, 초과하면 빨갛게 하고 전송을 막는다. 무제한이면 현재 글자 수만 보여 준다. [확정]
- 전송 전에 `checkPrompt`로 검사한다. 금지어가 있으면 전송이 막히고 어떤 단어가 걸렸는지(`word`)와 종류(`kind`: 주제어, 필수어, 추가금지어, 초성)를 안내한다. [확정]
- 서버가 거절하면(`prompt:rejected`) 같은 방식으로 안내한다. [확정]
- 상태별 모양: 입력 가능, 전송 후 대기(비활성, 로딩 표시), 연출 중(글은 쓸 수 있고 전송만 비활성), 페널티(5절). [제안]

### 4.2 설명창과 평가 연출
판정 결과는 `answer:ready` 이벤트에 이미 들어 있고, 화면은 그것을 순서대로 보여 줄 뿐이다. 판정을 다시 계산하지 않는다. [확정]

1. 답변 재생: 글자가 차례로 나온다. 속도는 서버가 준 `typeCps`다.
2. 평가 읽기: 평가 AI가 읽는 것처럼 문장 단위로 하이라이트가 이동한다. 서버가 준 `matched`의 필수어 위치를 강조하고, 분량 초과면 초과한 지점 이후를 표시한다. 시간은 서버가 준 `readMs`다.
3. 결과 공개: `verdict.pass`가 true면 검은 화면과 함께 PASS, false면 블루스크린과 함께 RETRY가 뜬다.
4. RETRY일 때는 이유(`reasons`)를 한 줄로 알려 준다: 필수어 부족(몇 개 중 몇 개 필요), 분량 초과(몇 자/몇 문장 중 몇), 잘림. [제안]

- 연출은 서버 판정보다 먼저 결과를 보여 주지 않는다. 결과가 PASS인데 RETRY 연출이 나오는 일이 없도록 연출 종류는 `verdict`만으로 정한다. [확정]
- 필수어 위치를 찾는 함수는 규칙 파일에 없어서 새로 추가한다(`locateMatches`, 06·07 문서). 없으면 하이라이트는 문장 단위 이동만 하고 필수어 강조는 생략한다. [제안]
- 상대가 먼저 맞혀 내 요청이 취소되면 연출 대신 "상대가 먼저 맞혔어요" 안내가 뜨고, 상대의 PASS 연출이 내 화면에서도 재생된다. [제안]

### 4.3 캐릭터 [제안]
- 평소엔 가만히 있고 PASS면 "야호", RETRY면 "엉엉" 반응을 한다. 페널티 동안에는 얼어붙는다. 이모지를 보내면 말풍선이 뜬다.
- 승리 화면에서는 환호와 축포, 패배에서는 우는 연출이다. [확정]

### 4.4 이모지 채팅 [확정]
- 이모지만 보낼 수 있다. 목록은 8개로 시작한다: 👍 🎉 😭 😮 🔥 😎 🤔 👏 [제안]
- 2초에 한 번만 보낼 수 있고 말풍선은 2초 뒤 사라진다. 상대에게도 보인다. [제안]

### 4.5 시간 바
- 줄어드는 체력바 모양이다. 서버의 `endsAt`와 보정한 서버 시각으로 계산한다. [확정]
- 10초 남으면 큰 숫자 10-9-8…이 나온다. [확정]
- 연결이 흔들려도 시간 바는 서버 시각 기준이라 점프하지 않고 천천히 보정한다. [제안]

### 4.6 점수와 연속 PASS
- 큰 점수는 `내 점수 : 상대 점수`다. [제안]
- 연속 PASS는 동그라미 3칸(●●○)으로 보여 준다. 레퍼런스 위쪽의 COMBO 칸에 대응한다. [제안]

### 4.7 나가기
- 나가기를 누르면 확인 모달이 뜨고, 예를 누르면 포기가 서버에 전달된다. 아니오면 닫힌다. [확정]

### 4.8 건너뛰기
- 입력창 옆에 건너뛰기 버튼을 둔다. 누르면 "상대 동의 대기"가 뜨고 다시 눌러 취소할 수 있다. 상대가 먼저 눌렀다면 "상대가 건너뛰기를 원해요"가 뜬다. [제안]

## 6. 레퍼런스 대응표

레퍼런스는 화면 구도와 정보 배치만 참고했다. 기존 게임의 캐릭터, 이름, 에셋은 쓰지 않는다. 대응이 애매한 칸은 만들지 않고 08 문서의 질문으로 넘겼다.

| 레퍼런스 영역 | 우리 요소 | 라벨 |
|---|---|---|
| 아래 이미지 ① 좌측 상단 프로필 | 내 프로필: 캐릭터 얼굴, 닉네임, 내 점수 | 제안 |
| 아래 이미지 ② 좌측 캐릭터 | 내 캐릭터(옷장에서 고른 것) | 제안 |
| 아래 이미지 ③ 우측 상단 프로필 | 상대 프로필: 캐릭터 얼굴, 닉네임, 상대 점수 | 제안 |
| 아래 이미지 ④ 우측 캐릭터 | 상대 캐릭터 | 제안 |
| 상단 가운데 큰 점수 | 내 점수 대 상대 점수 | 제안 |
| 캐릭터 위 말풍선 | 이모지 말풍선 | 제안 |
| 하단 입력 바 | 프롬프트 입력창과 전송 | 제안 |
| 하단 "돌아가기" 버튼 | 나가기(포기) 버튼 | 제안 |

| 위 이미지 COMBO | 연속 PASS 표시(0~2) | 제안 |

| 아래 이미지 가시 구체 오브젝트 | 대응 없음. 아이템이나 장애물 같은 것은 기획에 없다 | 미정 |
| 위 이미지 HOLD, NEXT | 대응 없음. 다음 문제를 미리 보여 주면 서버가 문제를 미리 내보내야 해서 부정행위 방지와 충돌한다 | 미정 |
| 위 이미지 KOS | 대응 없음. 상대에게 건 페널티 횟수 같은 값을 쓸 수 있으나 기획에 없다 | 미정 |

## 7. 하이라이트 튜토리얼(S13) [제안]

- 연습하기에서 서버 없이 로컬로 돈다. 문제는 쉬움 하나로 고정하고, AI 답변은 미리 준비한 두 개다(첫 전송은 RETRY용, 두 번째는 PASS용). 실제 `promptRules.js`로 금지어와 판정을 하고, 화면 컴포넌트는 대전 화면과 같다.
- 하이라이트 박스는 해당 요소만 밝게 하고 나머지를 어둡게 한다. 4단계다.

| 단계 | 하이라이트 | 안내 |
|---|---|---|
| 1 | 주제문 룰렛 | 주제와 필수어, 분량을 읽고 AI가 그것을 말하게 해야 해요 |
| 2 | 프롬프트 입력창 | 주제어와 필수어는 쓸 수 없어요. 써 보고 전송하세요(일부러 금지어를 써 보도록 유도해 막히는 모습을 보여 준다) |
| 3 | 설명창 | AI 답변이 나오고 평가 연출을 읽어요. 첫 전송은 RETRY가 떠요 |
| 4 | 시간 바와 연속 PASS 칸 | 한 번에 맞히면 연속 PASS가 쌓이고 3번이면 상대를 5초 멈춰요. 두 번째 전송에서 PASS를 경험 |

- 진행 중 건너뛰기 버튼을 눌러 튜토리얼을 끝낼 수 있다. [제안]
- 튜토리얼의 방식 자체(가짜 답변 사용)는 확인 대기 중이다. 08 문서에 있다. [제안]
