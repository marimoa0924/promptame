# 06. 판정과 AI

## 1. 규칙 파일(`promptRules.js`)이 하는 일 (코드 확인 완료)

이 절은 실제 코드와 테스트(10개 통과)를 읽고 쓴 것이다. [확정]

| 함수 | 입력 | 출력 | 메모 |
|---|---|---|---|
| `checkPrompt(prompt, problem, promptLimit=null)` | 프롬프트, 문제, 글자 제한 | `{ok:true}` 또는 `{ok:false, code, ...}` | code는 `EMPTY`, `TOO_LONG`, `FORBIDDEN`, `LENGTH_SPEC`(분량을 숫자로 직접 요구, `match`에 걸린 표현). `FORBIDDEN`에는 `word`와 `kind`(topic, keyword, extra, initials)가 붙음 |
| `checkAnswer(answer, problem, lengthRule, difficultyRules)` | AI 답변, 문제, 분량 | `{pass, keywordOk, lengthOk, matched, needed, length:{type,limit,actual}}` | 필수어는 공백, 대소문자, 특수문자를 무시한 부분 문자열로 센다 |
| `drawQuestion(data, difficulty, usedIds, rng)` | 문제 데이터, 난이도, 이미 나온 번호 | `{problem, lengthRule}` | 안 나온 문제 우선. 다 쓰면 같은 풀에서 다시 뽑음. 분량은 8개 중 독립으로 뽑음 |
| `countChars`, `countSentences` | 글 | 숫자 | 글자 수는 공백과 줄바꿈을 포함. 문장은 끝 기호나 줄바꿈 뒤에서 나누고 번호만 있는 조각은 제외 |
| `normalizeLoose`, `composeJamo`, `findForbidden`, `buildForbiddenList` | | | 내부 검사용. 낱자 풀어쓰기, 초성, 전각, 이모지 끼우기, 짧은 영어 단어 경계를 처리 |
| `PROMPT_LIMITS`, `DEFAULT_DIFFICULTY_RULES` | | | 상수 |

코드를 읽어 확인한 동작:

- 금지어는 주제어, 필수어, 추가금지어 전부다. 문제의 모든 주제어와 필수어, 추가금지어가 스스로 막히는지 테스트가 확인한다. [확정]
- 초성 검사는 한글 3글자 이상 단어만 한다. [확정]
- 짧은 영어 단어(4글자 이하)는 단어 경계에서만 막고 복수형(`dogs`)도 막는다. `dogma`는 통과한다. [확정]
- `checkAnswer`는 빈 답변이면 `lengthOk`가 false다. 필수어 필요 개수는 `difficultyRules`를 쓰고 없으면 필수어 전체 개수다. [확정]
- 주제 적합성은 평가하지 않는다. [확정]

## 2. 어디서 어떻게 쓰나 [확정]

| 위치 | 호출 | 목적 |
|---|---|---|
| 클라이언트 | `checkPrompt` | 전송 전 미리 검사(금지어, 길이, 빈 입력) |
| 서버 | `checkPrompt` | 같은 검사를 한 번 더 한다. 이것이 최종이다 |
| 서버 | `checkAnswer` | AI 답변 판정 |
| 서버 | `drawQuestion`(또는 아래의 `drawSequence`) | 판 시작 때 문제 목록 |

- 브라우저는 `<script type="module">`로 `/shared/promptRules.js`를 import하고 서버는 같은 파일을 import한다. 외부 라이브러리가 필요 없다. [확정]
- 서버는 Node ESM이므로 `package.json`에 `"type": "module"`이 필요하다. [제안]
- `promptLimit`의 null은 무제한이다. 서버는 `limit ?? 2000`으로 넘긴다(02 문서). [제안]

## 3. 규칙 파일에 추가해야 하는 것 [제안]

기존 동작은 바꾸지 않고 호환을 유지한다. 모델 전문의 작업이다(07 문서).

1. **잘림 값**: `checkAnswer(answer, problem, lengthRule, difficultyRules, opts)`에서 `opts.truncated`를 받는다. true면 분량 초과로 보아 `pass=false`, `lengthOk=false`로 한다. 결과에 `truncated`를 담는다.
2. **실패 이유 목록**: 결과에 `reasons`(`KEYWORD_SHORT`, `LENGTH_OVER`, `TRUNCATED`, `EMPTY`)를 추가해 UI가 RETRY 이유를 보여 주게 한다.
3. **필수어 위치와 분량 초과 위치**: `locateMatches(answer, keywords)`와 `locateOverflow(answer, lengthRule)`를 구현했다. 판정처럼 띄어쓰기, 특수문자, 대소문자를 무시하고 원문 위치를 돌려준다. 조합 방식이 다른 글자(NFC가 아닌 것)가 섞이면 칠하지 않는다.
4. **문제 목록 만들기**: `drawSequence(data, difficulty, count, rng)`로 40개를 한 번에 뽑는다. 난이도 풀을 다 쓰면 다시 섞어 이어 붙인다. 난수 시드를 받게 해서 테스트가 재현되도록 한다.
5. 위 4개에 대한 테스트를 추가한다.

## 4. 문제 데이터 갱신 흐름

현재 데이터: 문제 80개(쉬움, 보통, 어려움, 매우 어려움 각 20개). 난이도는 4단계이고, 처음의 쉬움은 보통으로, 보통은 어려움으로, 어려움은 매우 어려움으로 옮기고 정말 쉬운 일상 주제 20개를 새로 쉬움에 넣었다. 단계별 필수어 최소 개수는 1, 1, 2, 3이다, 필수어는 전부 3개, 분량 규칙 8개(1~3문장, 50, 100, 150, 200, 300자)다. xlsx와 `problems.json`의 주제는 서로 일치한다. [확정]

1. `data/교육용_대전게임_문제데이터_v2.xlsx`의 시트(주제, 분량, 난이도)를 고친다. 이 파일이 원본이다. [확정]
2. `npm i xlsx` 후 `node tools/build-problems.mjs <xlsx> data/problems.json`을 실행한다. [확정]
3. 스크립트가 검증한다: 번호와 주제 중복, 난이도 미등록, 필수어 개수 부족, 필수어 2~8글자, 주제와 필수어의 겹침, 필수어 중복. 오류가 있으면 파일을 만들지 않고 끝난다. 한 글자 주제는 경고만 한다. [확정]
4. `node --test`로 규칙 파일 테스트를 돌린다. 특히 "모든 문제의 주제어와 필수어는 스스로 막혀요"가 통과해야 한다. [확정]
5. 서버를 다시 시작한다. 문제는 시작할 때만 읽는다. [제안]
6. 추가 개선: 스크립트가 "필수어 정확히 3개"를 검사하도록 한다. 지금은 난이도 최소 개수만 본다. [제안]
7. 옛 생성 스크립트 `from openpyxl import Workbook.py`는 현재 xlsx와 내용이 달라서(주제 "비", 미토콘드리아 필수어 "호흡" 등) 지운다. [제안]
8. 새 우회 방법이 발견되면 `promptRules.test.js`에 한 줄 추가하는 것을 관례로 한다(파일 맨 위 주석). [확정]

## 5. Gemini 호출 설정

| 항목 | 값 | 라벨 |
|---|---|---|
| 모델 | Gemini Flash 계열 중 성능이 낮고 싸고 토큰이 적은 쪽. 기본값은 `gemini-3.5-flash-lite`(2.5 flash-lite는 새 사용자에게 막혀 있다고 Google이 안내함). 가격과 한도는 모름 | 미정 |
| 입력 | 유저 프롬프트 그대로 한 개 `user` 메시지. 시스템 프롬프트 없음 | 확정 |
| 호출 방식 | 스트리밍 아님. 답변 전체를 받고 서버가 판정한 뒤 클라이언트가 고정 속도로 재생 | 제안 |
| 생각(thinking) 기능 | 끈다(`thinkingBudget: 0`). 모델이 이 설정을 거부하면 서버가 설정만 빼고 다시 보낸다. `gemini-3.5-flash-lite`는 실제로 이 설정을 400으로 거부했고, 뺀 호출은 1.3초에 성공했다(2026-10-02 실측). 이 모델에서 생각을 끄는 올바른 설정은 아직 모른다 | 제안 |
| 최대 출력 토큰 | 1024. 가장 긴 분량(300자)보다 넉넉한 값이며, 한국어 토큰 비율을 실제로 재서 조정 | 제안 |
| 온도 등 | 기본값 | 제안 |
| 응답이 잘림 | 종료 사유가 토큰 한도면 `truncated=true`로 판정에 넘겨 분량 초과로 실패 처리 | 제안 |
| 안전 필터로 빈 응답 | 같은 프롬프트로 자동 재시도, 시도로 세지 않음, 타이머는 멈추지 않음 | 제안 |
| 응답 한도 | 8초 | 제안 |
| 재시도 | 오류, 시간 초과, 빈 응답에 한해 최대 2회, 0.5초 간격 | 제안 |
| 모두 실패 | `attempt:void`를 보내고 다시 쓰게 함. 연속 카운트에 영향 없음 | 제안 |
| 동시 요청 | 플레이어당 1건 | 제안 |
| API 키 | 서버 환경변수 `GEMINI_API_KEY` | 확정 |
| 한도 초과(429) | 재시도 규칙을 따르되 서버 로그에 남김. 해커톤 시연 전에 사용 한도를 확인해야 한다 | 제안 |

서버 안에서 쓰는 모양 (스펙용 예시):

```js
// GeminiClient: 실제 구현과 목(mock)이 같은 모양이다
generate(prompt, { signal }) -> Promise<{
  status: 'OK' | 'EMPTY' | 'BLOCKED' | 'ERROR',
  text: string, truncated: boolean, finishReason: string|null,
  latencyMs: number, usage: { inTokens, outTokens } | null }>
```

- AI가 영어로 답하거나 엉뚱하게 답하는 것은 게임성으로 보고 막지 않는다. 한국어 필수어가 안 들어 있으면 RETRY가 된다. [확정]
- AI 답변 안에 금지어가 들어가도 문제 삼지 않는다(검사하지 않음). [확정]

## 6. 실패 처리 요약 [제안]

| 결과 | 서버 동작 |
|---|---|
| `OK` | 판정 진행 |
| `OK`이고 잘림 | 분량 초과로 판정 |
| `EMPTY`, `BLOCKED` | 같은 프롬프트로 재시도(최대 2회) |
| `ERROR`, 시간 초과 | 같은 방식으로 재시도 |
| 재시도 모두 실패 | `attempt:void`, 로그, 시도로 세지 않음 |

## 7. 비용 추정

가격은 쓸 모델이 정해진 뒤 공식 가격표로 채운다. [미정] 아래는 토큰 사용량만 추정한 것이다.

가정(전부 제안):

- 한국어는 글자당 1~1.5토큰으로 잡는다. 프롬프트 평균 100자는 약 150토큰, 최대 300자는 약 450토큰이다.
- 답변은 평균 200자(약 300토큰), 상한은 1024토큰이다. 생각 기능은 꺼서 숨은 출력 토큰이 없다.
- 한 사람이 1분에 평균 4번 전송한다. 즉 5분 판이면 두 사람이 합쳐 40번이다.

| 시나리오 | 호출 수 | 입력 토큰 | 출력 토큰 |
|---|---|---|---|
| 평균(5분) | 40 | 6,000 | 12,000 |
| 평균(2분) | 16 | 2,400 | 4,800 |
| 최악(5분, 300자와 1024토큰) | 40 | 18,000 | 40,960 |

- 비용 = 입력 토큰 × 입력 단가 + 출력 토큰 × 출력 단가. 단가를 모르므로 숫자로는 쓰지 않는다. [미정]
- 해커톤 시연 규모에서는 가격보다 무료 한도의 분당 요청 수가 먼저 문제될 수 있다. 시연 전에 확인한다. [제안]
- 이 추정은 실제 호출 측정으로 대체한다(07 문서의 모델 작업). [제안]
