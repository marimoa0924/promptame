# 09. 구현 상태

main에 올라온 UI와 서버(Express, Socket.IO)를 확인하고, 판정 모듈과 AI 호출을 연결한 결과다. 마지막 확인은 2026-10-02이다.

## 1. 확인한 결과

| 확인 | 결과 |
|---|---|
| `node --test` | 56개 통과(규칙 파일 16개, AI 클라이언트 8개, 닉네임 3개, 방 규칙 20개, 랭킹과 저장 9개) |
| 방 규칙 검증(`game/room.test.js`) | 가짜 AI와 짧은 시간 설정으로 판 진행을 돌려 확인했다: 같은 순서의 문제, 상대 프롬프트 비공개, 금지어와 빈 입력과 길이 초과가 전송으로 안 세어짐, PASS한 사람만 진행, RETRY 뒤 PASS는 연속에 안 들어감, 분량 초과는 RETRY, 3연속 시 상대 5초 정지, 건너뛰기, AI 실패 시 시도 미집계, 종료 유예, 무승부, 포기, 카운트다운 중 나가기, 한 번 더 하기, 대기방 만료, 재접속 |
| `npm run smoke` (서버 켠 상태) | 방 생성, 입장, 금지어 차단, 동시 진행, 재접속, 포기, 연습봇, 한 번 더 모두 통과 |
| 브라우저 실행(두 사람) | 코드 6자리로 입장, 같은 문제 배포, 금지어 경고와 서버 거절, 전송과 PASS 연출, 상대 화면에 답변은 보이고 프롬프트는 숨김, 상대 점수 갱신, 건너뛰기, 포기 확인 창, 상대 승리 화면과 로비 복귀가 동작. 화면 오류 없음(샌드박스에서 막힌 외부 폰트 요청만 실패) |
| Gemini 실제 호출 | 사용자 컴퓨터에서 `✅ Gemini 연결 확인 (1298ms)`를 확인했다(`gemini-3.5-flash-lite`, 생각 설정은 400으로 거부되어 빼고 호출). 게임 중 답변 품질과 분량 준수는 아직 확인 전이다 |

## 2. 연결한 것

| 항목 | 내용 |
|---|---|
| 문제 데이터 | `problems.json`의 60문제(필수어 3개, 분량 8개)를 쓴다. 판 시작 때 `drawSequence`로 40개 목록을 뽑는다 |
| 프롬프트 검사 | 서버가 `checkPrompt`로 최종 검사한다. 브라우저도 `/shared/promptRules.js`로 같은 파일을 받아 전송 전에 검사한다 |
| 판정 | 서버가 `checkAnswer`로 확정한다. 결과 이유(필수어 부족, 분량 초과, 잘림, 빈 답변)를 한국어로 보여 준다 |
| AI 호출 | `game/gemini.js`. 프롬프트를 시스템 프롬프트 없이 그대로 보내고, 생각 기능을 끄고, 최대 출력 1024토큰, 응답 한도 8초, 실패 시 최대 2번 재시도한다. 답변이 잘리면 분량 초과로 판정한다 |
| AI 실패 | 끝내 답이 없으면 `ai:void`로 알리고 시도로 세지 않는다 |
| 키가 없을 때 | 목 AI로 돌아간다. 연습봇과 튜토리얼도 항상 목 AI를 쓴다 |
| 규칙 파일 | `checkAnswer`에 `opts.truncated`와 `reasons`를 추가하고, `drawSequence`를 추가했다. 기존 동작은 그대로다 |

실행: `npm install`, `GEMINI_API_KEY=... npm run dev`. 환경변수는 `GEMINI_API_KEY`, `GEMINI_MODEL`(기본 `gemini-3.5-flash-lite`로 넣었지만 쓸 수 있는 모델인지 확인하지 못했다), `GEMINI_THINKING_BUDGET`(기본 0, 빈 값이면 필드를 보내지 않음)이다.

## 3. 확정 사항에 맞게 고친 것

| 어긋났던 것 | 고친 내용 |
|---|---|
| 상대의 프롬프트가 화면에 보였다 | 판이 끝날 때까지 서버가 보내지 않는다. 상대 보드에는 "비공개" 안내가 뜬다 |
| 채팅(자유 문장, 이모티콘) | 모두 없앴다. 봇의 이모티콘 반응과 튜토리얼 이모티콘 단계도 뺐다 |
| 방 코드 5자리 | 6자리로 바꿨다 |
| 카운트다운 중 나가면 상대 승리 | 판이 무효가 되어 대기실로 돌아간다 |
| 연습봇과 튜토리얼이 옛 주제 데이터에 의존 | 새 문제 데이터와 목 AI로 바꿨다. 튜토리얼은 광합성 3문장 이내로 시작한다 |

## 4. 스펙과 구현이 다른 것

2026-10-02 전수 대조 결과다. 맨 위 세 줄은 이번 대조에서 찾아서 고친 것이다.

| ID | 차이 | 처리 |
|---|---|---|
| D-A | 시간이 끝나면 AI 답변을 기다리지 않고 바로 끝냈다(스펙은 이미 보낸 요청을 8초 유예) | 고쳤다. 유예 중에는 새 전송을 받지 않고, 요청이 모두 끝나면 바로 종료한다. 입력창도 시간이 끝나면 닫힌다 |
| D-B | 한 번 더 하기에서 이전 판의 문제가 다시 나올 수 있었다 | 고쳤다. 이전 판에서 본 문제는 먼저 피해서 뽑는다(`drawSequence`의 `usedIds`) |
| D-C | 대기방 10분 만료, 메시지 크기 8KB 제한이 없었다 | 고쳤다. 만료되면 `room:closed`로 알리고 로비로 보낸다. 메시지는 8KB까지만 받는다 |
| D-1 | 두 번째 사람이 들어오면 곧바로 카운트다운이 시작된다(호스트 시작, 준비 버튼 없음) | 구현을 따른다. 스펙의 호스트 시작과 준비는 이후로 미룬다 [제안] |
| D-2 | 맵 4종을 고를 수 있다. 확정은 동양풍만 구현이다 | 질문 Q-10 |
| D-5 | 튜토리얼이 서버 방 하나로 돈다(목 AI). 첫 문제는 광합성이고 예시 프롬프트를 넣으면 PASS가 나온다. 스펙은 서버 없는 로컬 어댑터에 첫 전송 RETRY, 둘째 PASS | 구현을 따른다 [제안] |
| D-6 | 이모티콘 채팅 | 채팅 기능을 없애면서 함께 뺐다 [확정] |
| D-7 | 결과 화면에 두 사람의 프롬프트 공개가 없다 | 남은 일 [제안] |
| D-8 | 한 번 더 하기는 양쪽이 각자 누르면 시작한다. 10초 만료는 없다 | 구현을 따른다 [제안] |
| D-11 | `playerId`가 탭마다 따로 저장된다(sessionStorage). 스펙은 브라우저에 저장 | 시험이 쉬워서 구현을 따른다. 탭을 닫으면 다른 사람이 된다 [제안] |
| D-12 | 두 사람 모두 연결이 끊기면 먼저 시간이 지난 쪽이 패배하고 남은 쪽이 승리한다(스펙은 판 무효) | 남은 일. 영향이 작다 [제안] |
| D-13 | 방 제목 최소 2자를 검사하지 않는다(비우면 기본 제목) | 영향이 작아 둔다 [제안] |
| D-14 | 전송 최소 간격 1초, 초당 메시지 수 제한, 웹소켓 `Origin` 검사가 없다. 한 사람이 AI 답변 중에는 다음 전송이 막혀서(`busy`) 동시 요청 폭주는 이미 막혀 있다 | 남은 일. 공개 호스팅 전에 `Origin` 검사를 넣는 것을 권한다 [제안] |
| D-15 | 프롬프트 기록 불러오기(위아래로 내가 보낸 프롬프트 다시 불러오기)가 구현되어 있다. 스펙에 없었다 | 스펙에 추가한다. 내 프롬프트만 불러오고 상대 것은 아니다 [제안] |
| D-16 | AI가 응답하지 않을 때 재시도(최대 2번, 0.5초 간격)가 끝날 때까지 화면에 따로 표시가 없다. 최악 약 25초 | 남은 일 [제안] |
| D-9 | 프롬프트 제한 무제한을 0으로 보낸다(스펙은 null) | 서버 안에서 변환한다. 영향 없음 |
| D-10 | 이벤트 이름이 스펙(04 문서)과 다르다 | 구현의 이름을 따른다. 아래 5절 |

| D-D | 같은 문제가 계속 다시 나왔다(난이도당 문제가 20개뿐이고 방마다 같은 풀에서 새로 뽑았다) | 고쳤다. 기기별로 본 문제를 기억해서 두 사람이 본 문제를 먼저 피한다. 문제 자체가 20개뿐이라는 한계는 그대로다. 엑셀에 문제를 더 넣어야 근본적으로 해결된다 |
| D-E | 랭킹이 없었다(스펙은 이후 단계) | 요청에 따라 구현했다. 05 문서 4.3 |
| D-F | 분량을 숫자로 직접 요구하는 프롬프트가 통과했다(기획서는 분량 언급 금지) | 고쳤다. `LENGTH_SPEC`(02 문서) |

이전에 있던 차이 중 해결된 것: 건너뛰기 버튼(D-3), 닉네임 2~8자와 금칙어(D-4).

## 5. 실제 이벤트 (Socket.IO)

| 방향 | 이벤트 |
|---|---|
| 클라이언트에서 서버 | `room:create`, `room:join`(재접속 겸용), `room:leave`, `room:rematch`, `room:addBot`, `prompt:submit`, `player:typing`, `prompt:skip`, `ranking:get`(랭킹 목록과 내 순위) |
| 서버에서 클라이언트 | `room:state`(사람마다 따로 보내는 스냅샷), `ai:start`, `ai:chunk`, `ai:judge`, `ai:result`(판정 `verdict` 포함), `ai:void`, `player:typing`, `game:event`(`freeze`, `skip`), `game:end` |

## 6. 남은 일 (우선순위 순)

1. Gemini로 실제 판을 돌려 분량 준수와 응답 속도, 토큰 사용량을 측정한다(06 문서). 연결 자체는 확인됐다.
2. 결과 화면의 프롬프트 공개(D-7).
3. 맵 범위 결정(Q-10) 후 정리.
4. 닉네임 금칙어 목록 보강(Q-06).
5. 필수어 위치를 찾는 함수(`locateMatches`)로 평가 하이라이트에 필수어 강조 추가(선택).
6. 시연 환경과 README 정리.
