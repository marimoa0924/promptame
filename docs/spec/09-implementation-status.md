# 09. 구현 상태

main에 올라온 UI와 서버(Express, Socket.IO)를 확인하고, 판정 모듈과 AI 호출을 연결한 결과다. 마지막 확인은 2026-10-02이다.

## 1. 확인한 결과

| 확인 | 결과 |
|---|---|
| `node --test` | 102개 통과(규칙 파일 22개, AI 클라이언트 8개, AI 제공자 7개, 닉네임 3개, 방 규칙 30개, 랭킹과 저장 9개, 계정 16개, 습관 분석 7개) |
| 방 규칙 검증(`game/room.test.js`) | 가짜 AI와 짧은 시간 설정으로 판 진행을 돌려 확인했다: 같은 순서의 문제, 상대 프롬프트 비공개, 금지어와 빈 입력과 길이 초과가 전송으로 안 세어짐, PASS한 사람만 진행, RETRY 뒤 PASS는 연속에 안 들어감, 분량 초과는 RETRY, 3연속 시 상대 5초 정지, 건너뛰기, AI 실패 시 시도 미집계, 종료 유예, 무승부, 포기, 카운트다운 중 나가기, 한 번 더 하기, 대기방 만료, 재접속 |

## 2. 연결한 것

| 항목 | 내용 |
|---|---|
| 문제 데이터 | `problems.json`의 60문제(필수어 3개, 분량 8개)를 쓴다. 판 시작 때 `drawSequence`로 40개 목록을 뽑는다 |
| 프롬프트 검사 | 서버가 `checkPrompt`로 최종 검사한다. 브라우저도 `/shared/promptRules.js`로 같은 파일을 받아 전송 전에 검사한다 |
| 판정 | 서버가 `checkAnswer`로 확정한다. 결과 이유(필수어 부족, 분량 초과, 잘림, 빈 답변)를 한국어로 보여 준다 |
| AI 호출 | `game/gemini.js`. 프롬프트를 시스템 프롬프트 없이 그대로 보내고, 생각 기능을 끄고, 최대 출력 1024토큰, 응답 한도 8초, 실패 시 최대 2번 재시도한다. 답변이 잘리면 분량 초과로 판정한다 |
| AI 실패 | 끝내 답이 없으면 `ai:void`로 알리고 시도로 세지 않는다 |
| 키가 없을 때 | 목 AI로 돌아간다. 연습봇과 튜토리얼도 항상 목 AI를 쓴다 |
| 규칙 파일 | `checkAnswer`에 `opts.truncated`와 `reasons`를 추가하고, `drawSequence`를 추가했다. 기존 동작은 그대로다 |

실행: `npm install`, `GEMINI_API_KEY=... npm run dev`. 환경변수는 `GEMINI_API_KEY`, `GEMINI_MODEL`(기본 `gemini-3.5-flash-lite`로 넣었지만 쓸 수 있는 모델인지 확인하지 못했다), `GEMINI_THINKING_BUDGET`(기본 0, 빈 값이면 필드를 보내지 않음)이다.

| D-K | AI가 Gemini 하나였고 솔로 플레이가 없었다 | 요청에 따라 구현했다. 방 설정에서 Gemini, GPT, Claude 선택(키가 있는 것만), 솔로 플레이(개인 최고, 솔로 랭킹, 재화). 이벤트 `ranking:solo` 추가. 11 문서. GPT와 Claude는 실호출을 시험하지 못했다 |
| D-G | 난이도가 3단계였고 보통도 너무 어려웠다 | 4단계로 바꿨다. 기존 쉬움은 보통, 보통은 어려움, 어려움은 매우 어려움으로 옮기고 새 쉬움 문제 20개를 추가했다(엑셀 원본과 `problems.json` 모두). 필수어 최소 개수는 쉬움 1, 보통 1, 어려움 2, 매우 어려움 3이다. 화면의 난이도 선택도 4개다 |
| D-H | 문제가 난이도당 20개뿐이라 금방 반복됐다 | 난이도마다 100개(전체 400개)로 늘렸다. 엑셀 원본에 번호 81~400을 추가하고 `build-problems.mjs`로 `problems.json`을 다시 만들었다(검증 통과). 새 문제는 모두 필수어 3개와 영어 추가금지어를 갖고, 필수어는 전 문제에서 겹치지 않는다. 실제 AI가 필수어를 자연스럽게 말하는지는 판을 돌려 보며 다듬어야 한다 |

이전에 있던 차이 중 해결된 것: 건너뛰기 버튼(D-3), 닉네임 2~8자와 금칙어(D-4).

## 6. 남은 일 (우선순위 순)

스펙에서 구현할 수 있는 항목은 모두 구현했다. 아래는 사람이 확인하거나 정해야 하는 것과 이후 단계다.

1. Gemini로 실제 판을 돌려 분량 준수와 응답 속도, 토큰 사용량을 측정한다(06 문서). 연결 자체는 확인됐다.
2. 맵 범위 결정(Q-10), 닉네임 금칙어 목록 보강(Q-06), 시연 환경 정하기(Q-02).
3. 공개 호스팅 전: `ALLOWED_ORIGINS`와 `MAX_ROOMS` 확인, `store.json` 저장 위치 확인.
4. 이후 단계(스펙에서 미룬 것): 호스트 시작과 준비 버튼, 서버 없는 튜토리얼, 재화, 가챠, 참가비, 로그인, 진짜 임의 매칭.
