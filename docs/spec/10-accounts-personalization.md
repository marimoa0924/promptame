# 10. 계정과 개인화

로그인(구글 또는 게스트)을 바탕으로 성적, 캐릭터, 랭킹, 재화, 프롬프트 작성 습관을 계정에 쌓는다. 원래 스펙의 이후 단계였던 것을 요청에 따라 구현했다. [확정]

## 1. 로그인

| 방식 | 내용 | 라벨 |
|---|---|---|
| 게스트 | 버튼 한 번으로 계정이 만들어진다. 이 브라우저(localStorage의 토큰)에만 남는다 | 확정 |
| 구글 | 구글 로그인 버튼으로 받은 ID 토큰을 서버가 구글에 확인한다(`oauth2.googleapis.com/tokeninfo`). 대상(`aud`), 발급자, 만료를 검사한다. `GOOGLE_CLIENT_ID`가 있어야 켜진다 | 확정 |
| 게스트 -> 구글 | 게스트로 시작한 뒤 "내 기록"에서 구글 계정을 연결하면 기록, 재화, 캐릭터가 그대로 이어진다 | 확정 |
| 이미 있는 구글 계정 | 다른 게스트가 같은 구글 계정으로 로그인하면 기존 구글 계정으로 전환된다(게스트 기록은 따로 남는다) | 제안 |

- 로그인하지 않으면 방을 만들거나 들어갈 수 없다. 로그인 화면이 먼저 나온다. [확정]
- 방에 들어갈 때의 이름과 캐릭터는 계정의 것을 쓴다. 클라이언트가 보낸 값은 쓰지 않는다. [확정]
- 같은 계정의 두 탭은 서로 다른 `playerId`로 대결할 수 있지만, 랭킹과 재화는 "같은 계정끼리"라서 반영되지 않는다. 서로 다른 계정으로 시험하려면 시크릿 창이나 다른 브라우저를 쓴다. [제안]
- 게스트 계정은 같은 주소에서 1분에 5개까지 만들 수 있다. [제안]

## 2. 계정에 쌓이는 것

| 데이터 | 내용 |
|---|---|
| 프로필 | 닉네임(2~8자, 금칙어 검사), 캐릭터, 가진 캐릭터 목록, 재화 |
| 성적 | 판 수, 연습봇 판 수, 승/무/패, 맞힌 문제 수, 한 번에 맞힌 수, RETRY 수, 최고 연속 PASS |
| 최근 경기 | 최근 30판: 상대, 점수, 결과, 난이도, 랭크 점수 변화, 재화 변화 |
| 랭킹 | 랭크 점수와 등급(05 문서 4.3). 계정 번호가 키다 |
| 프롬프트 기록 | 최근 300개의 특징(길이, 시도 번호, PASS 여부, 틀린 이유, 사용한 방법). 본문은 최근 100개만 앞 200자까지 남긴다 |

- 튜토리얼과 무효 판(두 사람 모두 끊김)은 아무것도 남기지 않는다. [확정]
- 연습봇과 한 판은 성적과 프롬프트 기록은 남기지만 랭킹과 재화는 없다. [제안]
- 본인만 볼 수 있다. 상대에게는 닉네임, 캐릭터, 랭킹 정보만 보인다. [확정]
- "프롬프트·경기 기록 지우기"와 "계정 삭제"를 제공한다. [확정]

## 3. 재화와 캐릭터

05 문서 4.2, 4.4와 같다. 기본 4종은 처음부터 쓰고, 나머지는 상점(120코인)이나 뽑기(50코인)로 얻는다. 잠긴 캐릭터는 로비의 옷장에서 자물쇠가 보이고 누르면 상점이 열린다. 서버가 가진 캐릭터만 고를 수 있게 막는다. [확정]

## 4. 프롬프트 작성 습관 분석

AI를 쓰지 않고 규칙으로 계산한다(판정과 같은 원칙). 판이 끝날 때마다 보낸 프롬프트를 특징으로 바꿔 기록하고, 기록이 8개 이상 모이면 유형을 알려 준다. [확정]

### 4.1 프롬프트에서 찾는 특징 [제안]
| 특징 | 예 |
|---|---|
| 역할·상황 설정 | "나는 초등학교 교사야", "너는 선생님이야" |
| 듣는 사람 지정 | "아이들에게", "초등학생", "쉽게" |
| 짧게 요청 | "짧게", "간결하게", "핵심만" |
| 비유·예시 요청 | "예를 들어", "비유로", "처럼" |
| 단계·순서 요청 | "먼저", "그다음", "차근차근" |
| 특징·과정 묘사 | "과정", "원리", "모양", "만드는" |
| 질문형 | "?", "뭐야", "어떻게" |
| 줄 나누기·목록 | 줄바꿈, 번호, 글머리표 |

### 4.2 작성 유형 [제안]
상황 설정형(역할과 듣는 사람 지정이 많음), 비유·예시형, 단계 안내형, 장문 설명형(평균 90자 이상), 짧은 직설형(평균 28자 미만), 균형형. 위에서부터 먼저 맞는 것을 고른다.

### 4.3 보여 주는 것
- 유형 이름과 설명, 평균 길이, 첫 시도 성공률, 맞힐 때까지 평균 시도 횟수
- 방법별 사용 비율과, 그 방법을 쓴 프롬프트와 안 쓴 프롬프트의 성공률 비교(양쪽 3개 이상일 때)
- 틀린 이유 비율(필수어 부족, 분량 초과)
- 가장 도움이 될 팁 최대 3개(분량 초과가 잦음, 필수어가 안 담김, 성공률이 높은 방법 권유, 너무 짧거나 긺)
- 최근에 쓴 프롬프트 10개

### 4.4 한계
- 규칙(정규식)으로 찾기 때문에 말투에 따라 틀릴 수 있다. 예를 들어 "누나한테"처럼 듣는 사람을 가리키는 낱말이 목록에 없으면 못 찾는다. [제안]
- 분석 결과는 "이런 경향이 있다"는 참고용이다. [확정]
- Gemini로 더 자연스러운 코칭 문장을 만드는 것은 하지 않았다. 호출 비용이 늘고 판정은 코드로만 한다는 원칙과 다르기 때문이다. 원하면 이후에 추가할 수 있다. [제안]

## 5. 구글 로그인 설정 (운영)

1. 구글 클라우드 콘솔에서 OAuth 클라이언트 ID(웹 애플리케이션)를 만든다.
2. "승인된 자바스크립트 원본"에 서비스 주소를 넣는다. 개발은 `http://localhost:3000`, 운영은 `https://내도메인`이다. 구글은 localhost가 아닌 곳에서는 https를 요구한다.
3. `.env`(또는 호스팅의 환경변수)에 `GOOGLE_CLIENT_ID=발급받은값`을 넣고 서버를 다시 켠다.
4. 로그인 화면에 "Google로 로그인" 버튼이 나오면 성공이다. 아직 설정이 없으면 "서버에 GOOGLE_CLIENT_ID 설정이 있어야 해요"가 보인다.
5. AWS에서는 도메인과 https(예: 로드밸런서나 Nginx와 인증서)가 필요하고, `store.json`이 있는 디스크가 서버를 다시 켜도 남아야 한다(`DATA_FILE`로 위치 지정). 프록시 뒤라면 `ALLOWED_ORIGINS`에 서비스 주소를 넣는다. [제안]

## 6. 이 세션에서 확인하지 못한 것

- 실제 구글 로그인(실제 토큰과 구글 서버 연결)은 구글 클라이언트 ID가 없어서 시험하지 못했다. 토큰 검사 로직은 가짜 응답으로 시험했다. [확정]
- 기록이 충분히 쌓인 계정의 분석 화면은 미리 만든 기록으로 확인했다.
